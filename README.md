# GoldenTimeAED

자동심장충격기(AED) 위치 안내 웹앱. **인터넷이 없어도 동작한다.**

심정지 대응이 필요한 곳(지하 주차장, 엘리베이터, 지하철역)일수록 네트워크가 약하다.
그래서 전국 AED 데이터를 미리 기기에 받아두고, 오프라인에서는 지도 대신
간이 지도와 거리순 목록으로 안내한다.

| 상태 | 화면 |
|---|---|
| 온라인 | 네이버 지도 + 마커 |
| 오프라인 | Canvas 간이 지도(거리 동심원 + 나침반) + 거리순 목록 |

---

## 기능 설명

> 발표·제출용으로 정리한 절. 이 절만 그대로 복사해 쓸 수 있다.
> 수치는 모두 실측값이며 측정 조건을 함께 적었다.

### 한 줄 요약

전국 자동심장충격기(AED) **61,717곳**의 위치를 지도와 목록으로 안내하는 웹앱.
**인터넷이 끊긴 곳에서도 동작한다.**

### 만든 이유

심정지 대응의 골든타임은 4분이다. 그런데 **대응이 필요한 장소일수록 네트워크가 약하다** —
지하 주차장, 엘리베이터, 지하철역, 대형 건물 내부.

웹앱이 오프라인에서 동작하려면 방법은 하나뿐이다. **인터넷이 끊기기 전에 데이터를 미리
기기에 내려두는 것.** 이 앱은 전국 AED 데이터를 사용자 휴대폰에 통째로 저장해두고,
네트워크가 없을 때는 저장본만으로 안내한다.

### 주요 기능

**1. 지도에서 주변 AED 찾기 (온라인)**
네이버 지도 위에 AED를 빨간 하트로 표시한다. 마커를 누르면 기관명·설치 위치·주소가 나온다.
화면을 옮길 때마다 서버에 묻지 않고 기기에 저장된 데이터에서 바로 걸러내므로 지연이 없다.

**2. 인터넷 없이 사용하기 (핵심 기능)**
네트워크가 끊기면 지도 대신 **간이 지도 화면**으로 자동 전환된다.
- 내 위치를 중심에 두고 주변 AED를 배치
- 100m / 300m / 500m 거리 동심원과 방위 표시
- 휴대폰을 돌리면 화면이 함께 회전하는 **나침반 연동**
- 가장 가까운 3곳은 번호를 붙여 아래 목록과 바로 연결

GPS는 네트워크 없이도 동작하므로 "내 위치에서 가장 가까운 AED"라는 핵심 가치가
오프라인에서도 그대로 유지된다.

**3. 거리순 목록**
가까운 순으로 정렬해 방향(북동 등), 직선거리, 설치 위치를 보여준다.
항목을 누르면 상세 정보와 함께 휴대폰의 지도 앱으로 좌표를 넘길 수 있다.
이 목록은 온라인에서도 상단 '목록' 버튼으로 언제든 볼 수 있다.

**4. 기관명·주소 검색 — 이것도 오프라인에서 된다**
"세종대로", "서울시청"처럼 기관명이나 주소를 입력하면 해당 지점으로 이동하고,
그곳을 기준으로 주변 AED가 다시 정렬된다.

외부 지도 검색 API를 쓰지 않고 **기기에 저장된 61,717건을 직접 훑는다.** 그래서
인터넷이 없어도 검색이 동작한다. PC 브라우저는 GPS가 없어 위치를 못 잡는 경우가 많은데,
그때 이 검색이 앱에 들어가는 유일한 경로가 된다.

**5. 홈 화면에 설치 (PWA)**
브라우저 주소창을 거치지 않고 아이콘 한 번으로 실행할 수 있다.
응급 상황에서 앱을 찾는 시간을 줄이고, 저장된 데이터가 지워지지 않도록 보호한다.

**6. 매일 자동 데이터 갱신**
공공데이터포털(safetydata.go.kr) API에서 매일 새벽 전국 데이터를 수집해 자동 배포한다.
사람 손이 필요 없고, 사용자는 앱을 열 때마다 최신 여부만 확인해 바뀐 날에만 내려받는다.

### 기술적 특징

**서버도 데이터베이스도 없다.**
상시 구동되는 API 서버와 DB를 모두 걷어냈다. 데이터는 하루 한 번만 갱신되면 충분하므로,
수집 결과를 정적 파일로 만들어 배포하는 구조로 바꿨다. 그 결과:
- 서버 운영비 **0원**, 서버 장애로 앱이 멈출 일이 없음
- 관리해야 할 비밀키가 **1개**로 축소
- 배포 절차가 사라짐 — 데이터가 갱신되면 자동으로 반영

**핵심 기능이 모두 네트워크와 무관하다.**
지도 타일만 온라인이 필요하고, 그 외 위치 측정·거리 계산·검색·목록은 전부 기기 안에서
끝난다. 검색까지 외부 API 없이 만든 것은 "인터넷이 없을 때 쓰는 앱"이라는 전제를
한 곳도 어기지 않기 위해서다.

**어떤 실패도 앱을 멈추지 않는다.**
지도가 안 뜨든, 네트워크가 끊기든, 설정이 잘못됐든 **모든 실패는 오프라인 화면으로 흡수된다.**
응급 상황에 쓰는 앱이 오류 화면으로 잠기는 일이 없도록 설계했다.

**외부 의존성을 최소화했다.**
프론트엔드는 프레임워크·빌드 도구 없이 순수 HTML/CSS/JS 약 1,900줄로 구현했다
(npm 패키지 0개). 데이터 수집 스크립트도 외부 라이브러리 2개만 사용한다.
의존성이 적을수록 시간이 지나도 그대로 동작한다.

### 정량 지표

| 항목 | 값 |
|---|---|
| 수록 AED | **61,717곳** (전국, 매일 자동 갱신) |
| 오프라인 커버리지 | 전국 100% (일부 지역이 아닌 전량을 기기에 저장) |
| 최초 실행 | **1.8초** — 전량 내려받아 기기에 저장 완료까지 |
| 재방문 실행 | **0.2초** — 저장본에서 바로 표시 |
| 데이터 전송량 | **2.4MB** (원본 10.8MB, 압축 전송) |
| 서버 운영비 | **0원** (상시 서버·DB 없음) |
| 런타임 의존성 | npm 패키지 **0개** / Python 라이브러리 2개 |

> 실행 시간은 로컬 환경(유선 네트워크, 데스크톱 브라우저) 실측값이다.
> 모바일 셀룰러 환경에서는 최초 실행이 더 걸릴 수 있다.

## 구조

```
[GitHub Actions cron, 매일 01시 KST]
   safetydata.go.kr API → 정적 스냅샷(JSON) → 저장소에 커밋 → Cloudflare Workers
                                                              │
                                        사용자가 온라인으로 접속 시 1회 다운로드
                                                              ▼
                                                    기기 IndexedDB에 저장
                                                              │
                                                  이후 오프라인에서도 동작
```

상시 구동되는 API 서버도, 데이터베이스도 없다. 데이터는 하루 1회만 갱신되면 충분하고,
프론트엔드는 정적 파일과 기기에 저장된 데이터만으로 동작한다.
스냅샷이 저장소에 있으므로 push가 곧 배포이고, 필요한 시크릿은 `SAFETYDATA_API_KEY` 하나다.
